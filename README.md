# Практическая работа № 2 — вариант 13

Дисциплина: «Конфигурационное управление».

## Описание

Проект предназначен для анализа и визуализации зависимостей
пакетов Alpine Linux APK.

Текущий этап: 1 — минимальный прототип с конфигурацией.

На этом этапе программа принимает параметры командной строки,
проверяет их и выводит настройки в формате ключ=значение.

Загрузка зависимостей, обход графа и создание изображения
будут добавлены на следующих этапах.

## Требования

- Python 3.10 или новее.
- Bash для запуска run.sh.

Используется стандартная библиотека Python.
Установка сторонних Python-пакетов и отдельная сборка не требуются.

## Структура проекта

- main.py — точка запуска из корня проекта.
- src/main.py — чтение, проверка и вывод параметров.
- src/__init__.py — обозначение пакета Python.
- tests/test_cli.py — автоматические проверки первого этапа.
- tests/*.json — тестовые графы для следующих этапов.
- run.sh — запуск программы и тестов.
- .gitignore — исключения для служебных файлов Git.

## Параметры командной строки

| Параметр | Назначение | Значение по умолчанию |
| --- | --- | --- |
| --package | Имя анализируемого пакета | Обязательный |
| --repository | HTTP(S) URL или путь к тестовому JSON | Обязательный |
| --test | Включить режим тестового репозитория | Выключен |
| --output | Путь к изображению SVG | graph.svg |
| --filter | Подстрока для исключения пакетов | Пустая строка |

В тестовом режиме имя пакета должно состоять из больших
латинских букв, а указанный файл должен существовать.

Родительская папка выходного файла должна существовать.
Расширение выходного файла — .svg.

Пустой фильтр отключает исключение пакетов.
Фильтр учитывает регистр и допускает буквы латинского алфавита,
цифры и символы + _ . -.
Фильтр не должен исключать сам анализируемый пакет.

На первом этапе параметры только проверяются и выводятся.
Фильтрация графа и создание SVG пока не выполняются.

## Функции

- build_parser() — описывает доступные параметры и справку.
- validate_package() — проверяет имя пакета.
- validate_repository() — проверяет URL или наличие файла.
- validate_output() — проверяет расширение и папку результата.
- validate_filter() — проверяет фильтр.
- arguments(argv=None) — читает параметры и выполняет проверки.
- main(argv=None) — выводит настройки и возвращает код успеха.

Аргумент argv позволяет передавать список параметров из тестов.
При значении None параметры берутся из командной строки.

## Запуск

Показать справку:

```bash
bash run.sh --help
```

Запустить с настоящим адресом репозитория:

```bash
bash run.sh \
  --package zlib \
  --repository https://dl-cdn.alpinelinux.org/alpine/v3.22/main/x86_64 \
  --output graph.svg \
  --filter ""
```

Запустить в тестовом режиме:

```bash
bash run.sh \
  --package A \
  --repository tests/chain.json \
  --test
```

Запуск напрямую через Python также поддерживается:

```bash
python main.py --help
```

## Проверка ошибок

Пример неправильного URL:

```bash
bash run.sh --package zlib --repository not-a-url
```

Ожидается сообщение:

```text
--repository: нужен полный HTTP(S) URL
```

Код завершения успешного запуска — 0.
Код ошибки параметров командной строки — 2.

## Автоматические тесты

Запуск через скрипт:

```bash
bash run.sh --tests
```

Запуск напрямую:

```bash
python -m unittest discover -s tests -v
```

Проверяются успешный вывод настроек, неправильные имя пакета,
URL, расширение изображения и фильтр, отсутствие тестового файла
и успешное включение тестового режима.

Для первого этапа ожидается 7 успешно выполненных тестов.
