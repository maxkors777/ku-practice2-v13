## Требования stage 3 и реализация

1. BFS без рекурсии: deque хранит пары (вершина, глубина).
2. Максимальная глубина: начальный пакет имеет глубину 0; вершины на
   границе сохраняются, но исходящие зависимости не раскрываются.
3. Подстрока --filter исключает имена пакетов, а не номера версий.
4. visited отмечается при постановке в очередь: циклы завершаются;
   рёбра к уже обнаруженным вершинам сохраняются.
5. --test читает JSON с именами A-Z; примеры ниже и tests/*.json.
6. Этап сохраняется отдельным коммитом после проверки.

Python 3.10+, стандартная библиотека; Bash для run.sh.
Для настоящего PyPI нужен интернет. Пакеты для анализа не устанавливаются.
Программа не вызывает pip и не использует библиотеки получения зависимостей.

## Демонстрации тестового режима

```bash
bash run.sh --package A --version 1.0 --repository tests/chain.json \
  --test --max-depth 0
bash run.sh --package A --version 1.0 --repository tests/chain.json \
  --test --max-depth 1
bash run.sh --package A --version 1.0 --repository tests/chain.json \
  --test --max-depth 2
```

Ожидаемые результаты: только A; затем A -> B и B -> (нет);
затем полная цепочка A -> B, B -> C, C -> (нет).

```bash
bash run.sh --package A --version 1.0 --repository tests/diamond.json \
  --test --max-depth 2 --filter B
```

Результат: A -> C, C -> D, D -> (нет). Общая вершина D сохраняется
через разрешённую ветвь C. Путь через B не обходится.

```bash
bash run.sh --package A --version 1.0 --repository tests/cycle.json \
  --test --max-depth 10
bash run.sh --package A --version 1.0 --repository tests/isolated.json \
  --test --max-depth 10
```

Цикл A -> B -> C -> A завершается. Изолированный пакет выводится
как A -> (нет). Все ссылки тестового графа должны быть объявлены ключами.

## Настоящие Python-пакеты

```bash
bash run.sh --package requests --version 2.32.3 \
  --repository https://pypi.org/pypi --max-depth 2
bash run.sh --package requests --version 2.32.3 \
  --repository https://pypi.org/pypi --max-depth 2 --filter urllib3
bash run.sh --package six --version 1.16.0 \
  --repository https://pypi.org/pypi --max-depth 2
```

Вершины имеют подписи name@version; запрошенные зависимостью extras
показываются как name[extra]@version. Разные версии не склеиваются.
Строки выводятся в порядке BFS, соседи сортируются для воспроизводимости.
Конкретные выбранные версии зависят от текущего состояния репозитория
и установленной версии Python, поэтому могут отличаться между компьютерами.

Прямые требования разбираются из requires_dist конкретной версии.
Учитываются маркеры текущего окружения и extras, запрошенные зависимостью.
Дополнительные возможности корневого пакета CLI отдельно не запрашивает.
Неактивные и исключённые зависимости не вызывают запросов их каталогов.
Для включённого требования выбирается максимальная подходящая версия.
Каталоги имён, метаданные релизов и решения кэшируются на время запуска.
Не раскрываются зависимости вершин на максимальной глубине.
Корневой релиз проверяется даже при глубине 0.

## Область модели

Собственный разбор поддерживает числовые релизы, epoch, pre/post/dev,
локальную часть, сравнения, AND через запятую, ~= и wildcard ==/!=.
Предварительные релизы выбираются только при явном запросе в ограничении.
Поддерживаются логические маркеры AND/OR, скобки, сравнения и in/not in.
Заведомо несовместимые requires_python и отозванные версии зависимостей
отбрасываются по каталогу файлов. Wheel-теги архитектуры не анализируются.

Это граф объявленных зависимостей, а не полный solver pip: ограничения
разных ветвей не объединяются с откатом; возможны разные версии одного
имени. Не моделируются установленные пакеты, lock-файлы и сборка.
Git/file/direct-URL требования и нестандартные версии отклоняются,
если такая зависимость активна и не исключена фильтром.
JSON API и его метаданные должны быть доступны в репозитории.
Полного покрытия всех расширений PEP 440/508 не заявляется.

Спецификации:
https://packaging.python.org/en/latest/specifications/version-specifiers/
https://packaging.python.org/en/latest/specifications/dependency-specifiers/
https://docs.pypi.org/api/json/

## Устройство

- src/main.py — прежний CLI, выбор источника и запуск BFS.
- src/repository.py — сохранённое получение прямых требований stage 2.
- src/graph.py — JSON, подписи вершин, BFS, фильтрация и печать.
- src/python_graph.py — требования, каталоги и ленивый источник PyPI.
- src/versions.py — собственное сравнение и выбор версий.
- src/markers.py — безопасный разбор условий; eval не используется.
- tests/ — проверки CLI, HTTP, графа, версий и маркеров.

Рекурсия присутствует только в разборе скобок маркера окружения;
обход графа выполняется исключительно очередью, без рекурсии.
