# Практическая работа № 2 — вариант 13

Дисциплина: «Конфигурационное управление».

Текущий этап: 5 — визуализация графа зависимостей.

## Описание

Программа анализирует зависимости пакетов Alpine Linux APK
или локального тестового репозитория JSON.

Возможности:

- чтение настроек из командной строки;
- самостоятельная загрузка и разбор APKINDEX;
- поиск прямых и транзитивных зависимостей;
- обход BFS без рекурсии;
- обработка циклов;
- фильтрация пакетов по подстроке;
- поиск обратных зависимостей;
- формирование PlantUML;
- сохранение изображения SVG через PlantUML.

Менеджеры пакетов и сторонние библиотеки для получения
зависимостей внутри программы не используются.

## Требования и сборка

- Python 3.10 или новее.
- Bash для запуска run.sh.
- Интернет для загрузки настоящего индекса.
- Java 17 или новее и PlantUML JAR для визуализации.

Python-библиотеки устанавливать не требуется.
Отдельная сборка проекта не нужна.

Все команды выполняются из корня проекта.

## Параметры

| Параметр | Назначение | По умолчанию |
| --- | --- | --- |
| --package | Начальный пакет анализа | Обязательный |
| --repository | URL индекса, каталога или путь JSON | Обязательный |
| --test | Читать тестовый JSON | Выключен |
| --output | Путь изображения SVG | graph.svg |
| --filter | Исключать имена с подстрокой | Пустая строка |
| --reverse | Искать обратные зависимости | Выключен |
| --visualize | Сохранить PlantUML и SVG | Выключен |
| --jar | Путь к PlantUML JAR | tools/plantuml.jar |

В тестовом режиме файл должен существовать.
Имена тестовых пакетов состоят из больших латинских букв.

Фильтр учитывает регистр. Пустой фильтр отключён.
Начальный пакет не должен попадать под фильтр.
Исключённые вершины не посещаются.
Узлы, доступные только через них, также исчезают из результата.
Если есть другой разрешённый путь, узел сохраняется.

Расширение результата должно быть .svg.
Родительская папка результата должна существовать.

## Формат тестового графа

Ключ — пакет, значение — список его прямых зависимостей.
Каждая упомянутая зависимость должна быть объявлена ключом.

```json
{
  "A": ["B"],
  "B": ["C"],
  "C": []
}
```

JSON содержит данные графа.
Настройки программы поступают через командную строку.

## Примеры

Справка:

```bash
bash run.sh --help
```

Цепочка и цикл:

```bash
bash run.sh --package A --repository tests/chain.json --test
bash run.sh --package A --repository tests/cycle.json --test
```

Одиночная вершина:

```bash
bash run.sh --package A --repository tests/isolated.json --test
```

Общая зависимость и фильтр:

```bash
bash run.sh \
  --package A --repository tests/diamond.json --test --filter B
```

Обратные зависимости:

```bash
bash run.sh \
  --package C --repository tests/chain.json --test --reverse
```

В обычном режиме A -> B означает, что A требует B.
В обратном режиме A -> B означает, что B требует A.
Сам корень не включается в итоговый список обратных зависимостей.

Настоящий репозиторий:

```bash
bash run.sh \
  --package xz \
  --repository https://dl-cdn.alpinelinux.org/alpine/v3.22/main/x86_64
```

Визуализации трёх настоящих пакетов:

```bash
mkdir -p out
REPOSITORY="https://dl-cdn.alpinelinux.org/alpine/v3.22/main/x86_64"
for package in zlib bzip2 xz; do
  bash run.sh --package "$package" --repository "$REPOSITORY" \
    --visualize --output "out/$package.svg"
done
```

Для каждого пакета создаются .puml и .svg.
SVG можно открыть в браузере.
Фильтрация и обратный режим также применяются к изображению.

## Функции

### src/main.py

- build_parser() — описание параметров и справки.
- validate_package() — проверка имени пакета.
- validate_repository() — проверка URL или файла.
- validate_output() — проверка пути результата.
- validate_filter() — проверка фильтра.
- arguments(argv=None) — чтение и проверка настроек.
- load_graph(args) — выбор источника графа.
- print_graph(graph) — вывод связей.
- execute(args) — обход, выбор режима и отрисовка.
- main(argv=None) — запуск и обработка ошибок.

При argv=None параметры берутся из командной строки.
В тестах можно передать список параметров.

### src/repository.py

- parse_index(text) — разбор записей APKINDEX.
- unpack_index(data) — чтение архива в памяти.
- load_repository(address) — загрузка индекса с таймаутом 30 секунд.
- direct_dependencies(packages, name) — исходные требования поля D.
- dependency_name(requirement) — отделение ограничения версии.
- build_providers(packages) — карта поставщиков.
- resolve_dependency(requirement, packages, providers) — поиск пакета.
- repository_graph(packages) — построение графа репозитория.

### src/graph.py

- load_test_graph(path) — чтение и проверка JSON.
- bfs(graph, start, excluded="") — обход в ширину без рекурсии.
- reverse_graph(graph) — разворот рёбер всего доступного графа.

BFS использует deque и visited.
Вершина отмечается при добавлении в очередь.
Рёбра циклов сохраняются, повторные посещения предотвращаются.

### src/render.py

- to_plantuml(graph) — текст диаграммы с безопасными идентификаторами.
- render_svg(graph, output, jar="tools/plantuml.jar") — отрисовка.

PlantUML получает уже построенный граф и не ищет зависимости.
Исходный текст сохраняется рядом с SVG.
Ответ проверяется как документ SVG.
Таймаут отрисовки — 60 секунд.

## Ограничения APK

Используется один индекс APKINDEX формата v2.
Формат Packages.adb не поддерживается.

Поля: P — имя, V — версия, D — требования,
p — дополнительные предоставляемые имена.

Требования библиотек сопоставляются с пакетами через p.
Настоящее имя пакета имеет приоритет.

Если поставщик отсутствует или их несколько, зависимость
помечается как неразрешённая.
При достижении такого узла прямой обход сообщает об ошибке.
Несвязанные с корнем проблемы обходу не мешают.

Ограничения версий читаются, но их совместимость не вычисляется.
Это граф объявленных связей, не полный решатель установки apk.

Конфликты с префиксом ! не становятся рёбрами.
Повторные требования к одному пакету дают одно ребро.
Несколько записей одного имени в индексе отклоняются.

Обратный поиск ограничен выбранным индексом.
Неразрешённые требования не позволяют восстановить неизвестные
связи с пакетами из других репозиториев.

## Stage 3: ограничение глубины

Параметр --max-depth задаёт максимальную глубину анализа:
0 — только начальный пакет;
1 — начальный пакет и прямые зависимости;
2 — дополнительно зависимости второго уровня.

Без параметра выполняется полный обход.
Отрицательные и нецелые значения отклоняются.
На предельном уровне зависимости дальше не раскрываются.

Пример:
bash run.sh --package A --repository tests/chain.json --test --max-depth 1

Результат:
A -> B
B -> (нет)
