# Практическая работа №2 — stage 2

Проект Корсунского: maxkors777/ku-practice2-v13.
Основа — предоставленный принятый stage 1 с семью параметрами CLI.
Stage 2 добавляет сбор прямых зависимостей Python-пакетов.

## Требования

Python 3.10+, Bash для run.sh, интернет для реального репозитория.
Python-зависимостей для установки нет: только стандартная библиотека.
Программа не вызывает pip, apk, npm и не импортирует сторонние средства
получения зависимостей. Исследуемый пакет не устанавливается.

## Запуск

```bash
bash run.sh --help
bash run.sh --package requests --version 2.32.3 \
  --repository https://pypi.org/pypi --max-depth 2
bash run.sh --package six --version 1.16.0 \
  --repository https://pypi.org/pypi --max-depth 2
```

Все команды можно запускать через python main.py с теми же параметрами.
Указывайте версию в точном написании, опубликованном в репозитории.

## Семь настроек из stage 1

| Параметр | Назначение | По умолчанию |
| --- | --- | --- |
| --package | Имя Python-пакета | Обязательный |
| --repository | Корень JSON API или путь тестового JSON | Обязательный |
| --test | Режим тестового репозитория | Выключен |
| --version | Конкретная версия пакета | Обязательный |
| --output | Имя будущего SVG | graph.svg |
| --max-depth | Неотрицательная глубина | Обязательный |
| --filter | Подстрока фильтра | Пустая строка |

На stage 2 глубина, фильтр и имя SVG только проверяются: по условию
выводятся ВСЕ прямые требования, без BFS, фильтрации и создания картинки.
Чтение тестового графа добавляется в stage 3; пока попытка выполнить
анализ с --test завершается понятным сообщением. Чтение самого флага,
проверка имени A-Z и существования тестового файла сохранены из stage 1.
Версия имеет базовую проверку записи, а не полный валидатор PEP 440.

## Получение данных

Используется HTTP JSON API: <repository>/<package>/<version>/json.
Для PyPI repository равен https://pypi.org/pypi; если задан только
https://pypi.org, автоматически добавляется /pypi.
Произвольный сервер должен предоставлять совместимый JSON API.
Адрес /simple относится к другому протоколу и отклоняется.

Программа проверяет имя и версию полученного ответа, затем читает
info.requires_dist. URL не переключается на latest при отсутствии версии.
Требования выводятся построчно с исходными ограничениями версий,
условиями после ; и extras. Условия не вычисляются: это все объявленные
прямые требования, а не результат установки для текущего компьютера.
Зависимости найденных пакетов не запрашиваются.
Пустой список и null дают сообщение об отсутствии объявленных требований;
отсутствующее поле requires_dist считается неполными метаданными.
Читаются опубликованные JSON-метаданные; setup.py не исполняется.
Таймаут HTTP-запроса — 30 секунд.

Официальный API: https://docs.pypi.org/api/json/.

## Файлы и функции

- main.py — прежняя точка входа, импортирует src.main.
- src/main.py — семь параметров, проверки, execute() и обработчик main().
- src/repository.py — загрузка и проверка метаданных Python-пакета.
- tests/test_cli.py — 17 проверок интерфейса и выполнения stage 2.
- tests/test_repository.py — 14 офлайн-проверок источника данных.
- tests/*.json — сохранённые примеры для следующего этапа.
- run.sh — обычный запуск и --tests.
- .gitattributes — Bash-скрипты сохраняются с переводами строк LF.

Функции источника: normalize_name() сравнивает имена; validate_address()
проверяет корень API; validate_identity_values() — запись имени и версии;
metadata_url() собирает адрес релиза; validate_metadata() проверяет ответ;
read_dependencies() читает объявления; fetch_metadata() получает JSON;
direct_dependencies() объединяет получение данных и проверки.
