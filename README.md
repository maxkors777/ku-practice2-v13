## Что добавлено

Режим --reverse отвечает на вопрос: какие пакеты зависят от выбранного
пакета непосредственно или через цепочку других зависимостей?

При исходном A -> B -> C обратный обход от C даёт C -> B -> A.
В обратном выводе C -> B означает, что B использует C.
После разворота всего доступного графа используется неизменённый bfs()
из stage 3: очередь deque, без рекурсии, с фильтром и глубиной.
Сначала полностью строится область поиска, а уже затем выполняются
разворот и ограниченный обратный BFS. Разворот только исходящего
подграфа выбранного пакета потерял бы его внешних зависимых.

В итоговой строке «Обратные зависимости» сам начальный пакет исключается,
в том числе если он входит в цикл. В графе рёбра цикла сохраняются.

Python 3.10+, стандартная библиотека, Bash для run.sh.
Программа не вызывает pip и не использует внешние библиотеки
для получения зависимостей. Тесты выполняются без интернета.

## Демонстрация на тестовом репозитории

Цепочка, прямые и транзитивные обратные зависимости:

```bash
bash run.sh --package C --version 1.0 --repository tests/chain.json \
  --test --max-depth 2 --reverse
```

```text
C -> B
B -> A
A -> (нет)
Обратные зависимости: B, A
```

Ограничение обратного поиска ближайшим уровнем:

```bash
bash run.sh --package C --version 1.0 --repository tests/chain.json \
  --test --max-depth 1 --reverse
```

Результат: C -> B, B -> (нет), итог B.
При глубине 0 выводится только C и пустой итог.

Ромб с фильтром B:

```bash
bash run.sh --package D --version 1.0 --repository tests/diamond.json \
  --test --max-depth 2 --filter B --reverse
```

Результат: D -> C, C -> A, A -> (нет), итог C, A.

Цикл, петля и изолированный пакет:

```bash
bash run.sh --package A --version 1.0 --repository tests/cycle.json \
  --test --max-depth 10 --reverse
bash run.sh --package A --version 1.0 --repository tests/self_cycle.json \
  --test --max-depth 10 --reverse
bash run.sh --package A --version 1.0 --repository tests/isolated.json \
  --test --max-depth 10 --reverse
```

Цикл: A -> C, C -> B, B -> A, итог C, B; обход завершается.
Петля: A -> A, итог пустой. Изолированный пакет: A -> (нет), итог пустой.

## Область обратного поиска для настоящего PyPI

Метаданные одного релиза содержат его исходящие зависимости, а не
полный список всех пакетов реестра, использующих его.
Поэтому требуется явно задать набор исходных релизов через --roots.
Это поиск в заданной области, а не глобальный поиск по всему PyPI.

Формат файла:

```json
[
  {"package": "requests", "version": "2.32.3"},
  {"package": "httpx", "version": "0.27.2"}
]
```

Пример такого файла — tests/python_roots.json.
Сначала объединяются полные транзитивные графы этих пакетов и выбранного
релиза. Разворачиваются все рёбра объединения, затем применяется BFS
от выбранной пары (имя, версия, extras), с указанной глубиной.
Фильтр исключает имена до загрузки их каталогов; исключённые исходные
пакеты также не посещаются. Кэши используются совместно.

Пример, если среди выбранных исходных пакетов используется idna 3.20:

```bash
bash run.sh --package idna --version 3.20 --max-depth 2 --reverse \
  --repository https://pypi.org/pypi --roots tests/python_roots.json
```

Версии зависимостей выбираются по текущему каталогу и окружению Python.
Если исходные пакеты используют другую версию idna, заданная 3.20 может
не иметь зависимых в этой области. Для воспроизводимости тесты используют
фиксированные JSON-графы и контролируемые ответы HTTP.
Без --roots реальный режим --reverse отклоняется с пояснением.
В режиме --test весь репозиторий уже задан JSON, --roots не используется.

## Устройство и проверки

- src/reverse.py: reverse_graph() разворачивает весь замкнутый граф;
  read_root()/read_roots() проверяют область; universe_graph() объединяет
  графы исходных пакетов без ограничения глубины до обратного поиска.
- src/main.py: validate_reverse_options() проверяет настройки;
  root_node() определяет корень; selected_graph() выбирает направление;
  execute() выводит граф и итог зависимых.
- src/graph.py: прежний BFS, JSON и подписи; алгоритм не заменялся.
- tests/test_reverse.py: 18 новых тестов, включая CLI и PyPI-область.

```bash
bash run.sh --tests
```

Ожидается 70 тестов и OK. Проверены сложность функций <=10, строки <=80,
функции <=40 строк и не более 7 аргументов. В сравнениях нет числовых
литералов, кроме базовых 0 и 1. Имена констант сохранены из исправлений.
Коды: 0 — успех, 1 — ошибка выполнения, 2 — ошибка CLI.
