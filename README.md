# Практическая работа № 2 — вариант 13

Дисциплина: «Конфигурационное управление».

## Описание

Инструмент для анализа зависимостей пакетов Alpine Linux APK.

Текущий этап: 2 — сбор данных о прямых зависимостях.

Программа принимает параметры командной строки, скачивает
APKINDEX.tar.gz, самостоятельно разбирает индекс и выводит
прямые зависимости выбранного пакета.

Менеджеры пакетов и сторонние библиотеки для получения
зависимостей не используются.

## Требования и сборка

- Python 3.10 или новее.
- Bash для запуска run.sh.
- Интернет для обращения к настоящему репозиторию.

Используется стандартная библиотека Python.
Отдельная сборка и установка Python-пакетов не требуются.

## Структура проекта

- main.py — точка запуска из корня проекта.
- src/main.py — параметры, проверки и запуск анализа.
- src/repository.py — загрузка и разбор индекса APK.
- src/__init__.py — обозначение пакета Python.
- tests/test_cli.py — проверки параметров.
- tests/test_repository.py — проверки второго этапа.
- tests/*.json — тестовые графы для следующих этапов.
- run.sh — запуск программы и тестов.
- .gitignore — исключения для служебных файлов.

## Настройки

| Параметр | Назначение | По умолчанию |
| --- | --- | --- |
| --package | Имя анализируемого пакета | Обязательный |
| --repository | URL индекса или каталога репозитория | Обязательный |
| --test | Переключатель тестового режима | Выключен |
| --output | Путь к будущему изображению SVG | graph.svg |
| --filter | Подстрока для будущей фильтрации | Пустая строка |

На этапе 2 выполняется анализ настоящего репозитория.
Чтение тестового графа будет добавлено на этапе 3.
При запуске с --test программа сообщает об этом ограничении.

Параметры --output и --filter проверяются, но создание картинки
и фильтрация зависимостей пока не выполняются.

Имя пакета допускает латинские буквы, цифры и символы + _ . -.
Первый символ должен быть буквой или цифрой.

В тестовом режиме проверяются наличие файла и имя из букв A-Z.

Путь результата должен иметь расширение .svg.
Родительская папка должна существовать.

Фильтр учитывает регистр и допускает символы имени пакета.
Пустой фильтр означает отсутствие исключений.
Фильтр не должен исключать сам анализируемый пакет.

## Функции программы

### src/main.py

- build_parser() — описывает параметры и справку.
- validate_package() — проверяет имя пакета.
- validate_repository() — проверяет URL или наличие файла.
- validate_output() — проверяет путь результата.
- validate_filter() — проверяет фильтр.
- arguments(argv=None) — читает и проверяет настройки.
- main(argv=None) — загружает данные и выводит зависимости.

Аргумент argv позволяет передавать параметры из тестов.
При None используется командная строка.

### src/repository.py

- load_repository(address) — скачивает индекс с таймаутом 30 секунд.
- unpack_index(data) — читает архив в памяти.
- parse_index(text) — разбирает записи пакетов.
- direct_dependencies(packages, name) — возвращает прямые требования.

Поля индекса: P — имя, V — версия, D — зависимости,
p — дополнительные предоставляемые имена.

Зависимости выводятся как исходные требования из поля D.
Например, so:liblzma.so.5 обозначает требуемую библиотеку.
Сопоставление таких требований с пакетами будет добавлено
при построении графа.

Используется индекс APKINDEX формата v2.
Формат Packages.adb не поддерживается.

## Запуск

Справка:

```bash
bash run.sh --help
```

Прямые зависимости zlib:

```bash
bash run.sh \
  --package zlib \
  --repository https://dl-cdn.alpinelinux.org/alpine/v3.22/main/x86_64
```

Прямые зависимости xz:

```bash
bash run.sh \
  --package xz \
  --repository https://dl-cdn.alpinelinux.org/alpine/v3.22/main/x86_64
```

В --repository также можно передать полный URL APKINDEX.tar.gz.

Пример ошибки поиска пакета:

```bash
bash run.sh \
  --package no-such-package-v13 \
  --repository https://dl-cdn.alpinelinux.org/alpine/v3.22/main/x86_64
```

## Коды завершения

- 0 — успешное выполнение.
- 1 — ошибка загрузки, архива или поиска пакета.
- 2 — неправильные параметры командной строки.

## Тесты

```bash
bash run.sh --tests
```

Или напрямую:

```bash
python -m unittest discover -s tests -v
```

Всего 14 тестов: 7 проверок параметров и 7 проверок второго этапа.

Проверяются разбор индекса, прямые зависимости, отсутствие пакета,
некорректный индекс, чтение архива, адрес загрузки, вывод программы
и обработка сетевой ошибки.

Автоматические тесты не требуют интернета.
Сетевые вызовы подменяются подготовленными ответами.
